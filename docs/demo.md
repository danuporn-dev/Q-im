# Run sheet สาธิต Q-im (5–6 นาที)

โน้ตบุ๊ก (Windows + XAMPP) เป็น server ลูกค้าเปิดจากมือถือในเครือข่ายเดียวกัน ร้านและผู้ดูแลเปิดบนโน้ตบุ๊ก ใช้ `APP_ENV=development` และข้อมูลสมมติเท่านั้น

> **ความปลอดภัย:** ในโหมดนี้ทุกคนในเครือข่ายเดียวกันเข้าเป็นลูกค้าสาธิตได้โดยไม่มีรหัสผ่าน และข้อมูลส่งผ่าน HTTP ที่ไม่เข้ารหัส ให้ใช้ hotspot ของตัวเองที่มีรหัสผ่าน ไม่ใช้ Wi-Fi สาธารณะ และปิดตามหัวข้อ "หลังจบ" ทันที

## 1. ตั้งครั้งเดียว

1. ใน `.env` ตั้งค่าต่อไปนี้ ส่วน `LIFF_ID` ต้องว่าง

   ```ini
   APP_ENV=development
   POLL_SECONDS=2
   ```

   รหัสผ่านของร้านและผู้ดูแลทุกบัญชีคือค่า `SEED_DEMO_PASSWORD` ใน `.env` (ห้ามจดลงไฟล์อื่นหรือฉายขึ้นจอ)

2. เพิ่มท้าย `C:\xampp\apache\conf\extra\httpd-vhosts.conf` แล้ว Stop/Start Apache ใช้ Apache ไม่ใช้ `php -S` เพราะ `php -S` บน Windows รับได้ทีละคำขอ

   ```apache
   Listen 8080
   <VirtualHost *:8080>
       DocumentRoot "C:/xampp/htdocs/Q-im/public"
       <Directory "C:/xampp/htdocs/Q-im/public">
           AllowOverride All
           Require all granted
       </Directory>
       # เปิดเฉพาะเส้นทางของ Q-im: XAMPP แขวน /phpmyadmin, /server-status ฯลฯ ไว้กับทุก VirtualHost
       <LocationMatch "(?i)^/(?!$|index\.php$|(customer|merchant|admin|assets|api)(/|$))">
           Require all denied
       </LocationMatch>
   </VirtualHost>
   ```

   **ห้ามตัด `LocationMatch` ออก** หากตัดออก `/phpmyadmin` จะเปิดได้ผ่าน ngrok เพราะ XAMPP เห็นคำขอมาจากเครื่องตัวเอง (ทดสอบแล้วตอบ 200 เมื่อไม่มี และ 403 เมื่อมี)

3. เปิด Windows Firewall เฉพาะ port 8080 จากเครื่องใน subnet เดียวกัน (PowerShell แบบ Administrator)

   ```powershell
   New-NetFirewallRule -DisplayName "Qim demo 8080" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8080 -RemoteAddress LocalSubnet -Profile Private
   ```

   Rule เดิมที่ Windows เคยสร้างให้ `httpd.exe` มีผลต่อ port นี้ด้วย ถ้าเคยตอบ Block ไว้ต้องลบ rule Block นั้น และไม่ต้องเปิด port 80 หรือ 3306

| ร้าน | `demo_merchant_2` | ก๋วยเตี๋ยวเรือลุงหนวด (ลุงหนวด) | รหัส `SEED_DEMO_PASSWORD` |
| ร้าน | `demo_merchant_3` | ชื่นใจ เครื่องดื่ม (พี่ชื่น) | รหัส `SEED_DEMO_PASSWORD` |

ถ้าเคยตั้งรหัสสั้นให้บางบัญชีเพื่อซ้อมในเครื่อง (เช่น `12345678`) รหัสนั้นเปลี่ยนเฉพาะใน `qim_dev` และหายไปเมื่อรัน `demo-reset.php` ใหม่ ห้ามใช้รหัสสั้นเมื่อเปิดให้คนนอกเข้า

> **ก่อนเดโมผ่านอินเทอร์เน็ต (ngrok) ต้องเปลี่ยนรหัสผ่านก่อนทุกครั้ง** ทำตามลำดับ:
>
> 1. เปลี่ยน `SEED_DEMO_PASSWORD` ใน `.env` เป็นค่าใหม่ ยาวอย่างน้อย 12 ตัว และไม่เคยใช้ ส่งต่อ หรือฉายจอมาก่อน
> 2. รัน `C:\xampp\php\php.exe scripts\demo-reset.php --confirm` (ลบและสร้าง `qim_dev` ใหม่ ทุกบัญชีได้รหัสใหม่ และ session เดิมทั้งหมดหลุด)
> 3. รัน `C:\xampp\php\php.exe scripts\demo-history.php` ถ้าต้องการประวัติออเดอร์และสถิติย้อนหลัง
> 4. ตั้ง `DEMO_ACCESS_CODE` และตรวจรายการในหัวข้อ 5 ก่อนเปิด ngrok
>
> เหตุผล: รหัสเดิมอาจเคยพิมพ์ในแชท อยู่ในประวัติเทอร์มินัล หรือถูกตั้งสั้นไว้ตอนซ้อม ใครรู้รหัสก็เข้าเป็นร้านหรือผู้ดูแลผ่าน URL สาธารณะได้

### คีย์ QR รับอาหาร

ไม่ต้องตั้งอะไรเพิ่ม: เมื่อ `PICKUP_TOKEN_KEY` ใน `.env` ว่าง ระบบสร้าง `storage/keys/pickup.key` เองตอนออเดอร์แรกพร้อมรับ (ตรวจแล้วบนเครื่องนี้ ไฟล์ถูกสร้างและไม่ถูก commit) ถ้าหน้า admin › ระบบ ขึ้นแถบแดง "QR รับอาหารใช้ไม่ได้" หรือลูกค้าเห็น "แสดง QR รับอาหารไม่ได้ในขณะนี้" ให้ตรวจว่าโฟลเดอร์ `storage\keys` ไม่ได้ตั้งเป็น read-only หรือใส่ `PICKUP_TOKEN_KEY` ยาว 32 ตัวขึ้นไปใน `.env` ระหว่างนั้นร้านส่งมอบด้วยการพิมพ์เลขออเดอร์เต็มได้ ห้ามลบหรือเปลี่ยนคีย์ระหว่างสาธิต เพราะ QR ที่แสดงอยู่จะใช้ไม่ได้จนลูกค้าโหลดหน้าใหม่

## 2. รูปอาหาร

repo มีรูปจริงจาก Wikimedia Commons ให้ 23 เมนูแล้ว (CC0, สาธารณสมบัติ, CC BY, CC BY-SA ดูรายละเอียดที่ `public/assets/demo-food/CREDITS.md` หรือหน้า `/credits` ที่ลิงก์ "เครดิตรูปภาพ" ท้ายหน้าแรกของลูกค้า) อีก 8 เมนูไม่มีรูปที่ตรงเมนูและใบอนุญาตผ่าน จึงแสดงภาพวาด ไม่วางรูปเลยก็สาธิตได้: เมนูที่ไม่มีรูปแสดงภาพวาดตามหมวด (ข้าว เส้น ของทอด เครื่องดื่ม ของหวาน อื่น ๆ) และร้านแสดงภาพแผงร้าน ถ้าจะใช้รูปจริง ทำตามลำดับนี้

1. ใช้เฉพาะรูปที่ถ่ายเอง รูปที่เจ้าของร้านอนุญาตเป็นลายลักษณ์อักษร หรือรูปที่สัญญาอนุญาตยอมให้ใช้และดัดแปลง (เช่น CC0 หรือ CC BY พร้อมระบุผู้สร้าง) ห้ามใช้รูปจากเว็บที่ไม่ระบุสัญญาอนุญาต และห้ามใช้รูปที่เห็นใบหน้าคนหรือป้ายทะเบียน
2. วางไฟล์ใน `public/assets/demo-food/` ตั้งชื่อตาม slug ในตารางด้านล่าง นามสกุล `.jpg`, `.jpeg`, `.png` หรือ `.webp` เช่น `kaphrao-mu.jpg`
3. ใส่หนึ่งบรรทัดต่อไฟล์ใน `public/assets/demo-food/CREDITS.md` (ไฟล์ ผู้ถ่าย แหล่งที่มา สัญญาอนุญาต วันที่) สคริปต์จะพิมพ์ `Warning: ... has no line` ถ้าขาด
4. รัน `demo-reset.php` (หัวข้อ 3 ข้อ 5) ทุกรูปผ่านการตรวจเดียวกับที่ร้านอัปโหลด (D41): JPEG/PNG/WebP ไม่เกิน 3 MB ด้านสั้นอย่างน้อย 200 px ด้านยาวไม่เกิน 6000 px ระบบหมุนตาม EXIF ย่อเหลือไม่เกิน 1200 px ทำ thumbnail และลบข้อมูลกล้อง/ตำแหน่งออก ไฟล์ที่ไม่ผ่านขึ้น `Skipped <ไฟล์>: <เหตุผล>` แล้วเมนูนั้นใช้ภาพวาดแทน

## 3. ก่อนขึ้นเวที (15 นาที)

1. เสียบปลั๊ก แล้วปิด sleep: Settings › System › Power › Screen and sleep › Never ปิดการแจ้งเตือนของ Windows (Do not disturb)
2. เปิด hotspot มือถือหรือ Mobile hotspot ของ Windows ให้โน้ตบุ๊กและมือถืออยู่เครือข่ายเดียวกัน และตั้งเครือข่ายเป็น **Private** (Settings › Network & internet › เครือข่าย › Private network)
3. XAMPP Control Panel: Start **Apache** และ **MySQL**
4. หา IP: รัน `ipconfig` ดู `IPv4 Address` ของ adapter ที่เชื่อมเครือข่ายนั้น (Mobile hotspot ของ Windows มักเป็น `192.168.137.1`) ต่อไปเขียนว่า `<IP>`
5. คืนข้อมูลสะอาด **คำสั่งนี้ลบทุกแถวใน `qim_dev` และ session login ทั้งหมด**

   ```powershell
   C:\xampp\php\php.exe scripts\demo-reset.php --confirm
   ```

   ถ้าจะโชว์สถิติร้าน สร้างออเดอร์ย้อนหลัง 14 วัน (ข้อมูลสมมติ ไม่มีรีวิว วันนี้ยังว่าง คิวจึงเริ่ม Q-001):

   ```powershell
   C:\xampp\php\php.exe scripts\demo-history.php
   ```

6. แยกหน้าต่าง: ร้านใช้หน้าต่างปกติ ผู้ดูแลใช้หน้าต่าง incognito มือถือใช้แท็บ incognito (session แยกตามบทบาทอยู่แล้ว แต่การแยกหน้าต่างช่วยไม่ให้ค้างของเก่า) ปิดหน้าต่าง incognito เดิมทั้งหมดก่อน
7. Login ให้พร้อม และปิดคำถามให้จำรหัสผ่านก่อนฉายจอ

| หน้า | URL | เข้าใช้ |
|---|---|---|
| ลูกค้า (มือถือ) | `http://<IP>:8080/customer/` | แตะชื่อลูกค้าสาธิต |
| จำลองข้อความ LINE | `http://<IP>:8080/customer/#/messages` | ลูกค้าคนเดียวกัน |
| ร้าน (โน้ตบุ๊ก) | `http://localhost:8080/merchant/` | `demo_merchant_1` ป้าแดง, `demo_merchant_2` ลุงหนวด, `demo_merchant_3` พี่ชื่น, `demo_merchant_4` เจ๊หมวย, `demo_merchant_5` พี่บีม |
| ผู้ดูแล (โน้ตบุ๊ก) | `http://localhost:8080/admin/` | `demo_admin` |
| ตรวจว่า server ตอบ | `http://<IP>:8080/api/v1/health` | – |

สร้าง QR ของ URL ลูกค้าไว้ล่วงหน้าได้ แต่ IP เปลี่ยนตามเครือข่าย ต้องตรวจใหม่ทุกครั้ง

| PromptPay | ร้าน › ตั้งค่าร้าน › ใส่เบอร์มือถือ (ใช้เบอร์ทดสอบ ไม่ใช่ของจริง) › ติ๊กเปิด; ลูกค้าเลือก PromptPay ในตะกร้า เมื่อพร้อมจะเห็น QR PromptPay กับข้อความ "รอร้านตรวจสอบยอด"; ตอนส่งมอบร้านเลือก "PromptPay" แล้วกด ได้รับเงินแล้ว **ห้ามสแกนโอนเงินจริงบนเวที** |
| QR ใช้ครั้งเดียว | หลังส่งมอบ ลองสแกน QR เดิมอีกครั้ง จะขึ้น "QR นี้ใช้ไม่ได้แล้ว" |
| ความหนาแน่น/โรงอาหาร | หน้าแรก › เลือกโรงอาหาร › รับหลายออเดอร์ให้เห็นระดับเปลี่ยน |
| รายการโปรด/รีวิว | กดหัวใจในหน้าร้าน; หลังรับอาหาร ให้คะแนนในหน้าออเดอร์ |
| แจ้งเตือน | ลูกค้า › ปุ่มแจ้งเตือน; ร้าน › กด "เปิดเสียงเตือน" ก่อนเริ่ม |
| สถิติ | รัน `demo-history.php` ก่อน แล้วเปิด ร้าน › รายงาน |

ถ้าอยากโชว์คิวหลายคน: ใช้มือถือเครื่องที่สองเป็น **ต้นกล้า** สั่งร้านเดียวกันแล้วให้ร้านรับต่อจากมินท์ จะเห็น "มี 1 คิวก่อนหน้า"

กล้องสแกน QR เปิดได้เฉพาะ HTTPS หรือ localhost: ผ่าน ngrok ใช้กล้องได้; ผ่าน Wi-Fi แบบ `http://<IP>` ให้แตะ **ถ่ายรูป QR** หรือพิมพ์เลขออเดอร์เต็มแทน

## 5. เปิดผ่านอินเทอร์เน็ตด้วย ngrok (ทางเลือก)

ใช้เมื่อมือถือเข้าเครือข่ายเดียวกันไม่ได้ ทั้งโลกที่รู้ URL จะเข้าถึงหน้าเว็บได้ จึงใช้เฉพาะข้อมูลสาธิต เปิดเท่าที่จำเป็น และปิดทันทีเมื่อจบ ต้องตั้ง VirtualHost ในหัวข้อ 1 ก่อน

**ค่าใน `.env`** (สร้างรหัสเข้าชมใหม่ทุกงาน ใช้ 8 ตัวอักษรขึ้นไป ไม่ซ้ำกับรหัสผ่าน ห้าม commit)

```ini
APP_ENV=development
APP_URL=https://<ชื่อที่ได้>.ngrok-free.app
DEMO_ACCESS_CODE=<รหัสเข้าชม>
DEMO_PUBLIC=true
TRUSTED_PROXY=127.0.0.1,::1
POLL_SECONDS=2
LIFF_ID=
```

| ค่า | ผล |
|---|---|
| `DEMO_ACCESS_CODE` | ต้องกรอกรหัสก่อนแตะชื่อลูกค้าสาธิต ผิดเกิน 20 ครั้งใน 15 นาทีต่อ IP จะถูกพัก ว่าง = ไม่ถามรหัส **ห้ามเว้นว่างเมื่อเปิด ngrok** |
| `DEMO_PUBLIC` | ไม่ส่งรายละเอียด error, stack trace และชื่อ environment ให้ client ส่วน log ใน `storage/logs` เหมือนเดิม |
| `TRUSTED_PROXY` | เชื่อ `X-Forwarded-*` เฉพาะจาก ngrok ในเครื่อง ทำให้ cookie เป็น `Secure`, ตรวจ Origin ถูก และนับ rate limit ตาม IP ผู้ชมจริง ห้ามใส่ IP ของเครื่องอื่น |
| `APP_URL` | ใช้ในลิงก์ของข้อความแจ้งเตือนเท่านั้น หน้าเว็บใช้ที่อยู่แบบ relative |

แก้ `.env` แล้วมีผลทันที ไม่ต้อง restart

**เปิด** (ใส่ authtoken ของตัวเองด้วย `ngrok config add-authtoken` ครั้งเดียว)

```powershell
ngrok http http://127.0.0.1:8080 --inspect=false
```

- ชี้ไปที่ port 8080 เท่านั้น **ห้ามเปิด port 80** เพราะเป็น htdocs ทั้งหมดพร้อม phpMyAdmin
- `--inspect=false` ปิดหน้า `http://127.0.0.1:4040` ที่เก็บคำขอรวมถึงรหัสผ่าน
- ไม่ใช้ `--host-header=rewrite` เพราะระบบต้องเห็น Host สาธารณะ
- ถ้าใช้ ngrok อย่างเดียว เปลี่ยน `Listen 8080` เป็น `Listen 127.0.0.1:8080` และไม่ต้องเปิด firewall ในหัวข้อ 1

**เช็กลิสต์ก่อนเปิดให้ผู้ชม**

- [ ] รัน `demo-reset.php --confirm` ลบ session เดิมทั้งหมด รวมถึงที่สร้างก่อนตั้งรหัส
- [ ] `SEED_DEMO_PASSWORD` ไม่เคยเผยแพร่ที่ใด ถ้าเคยส่งต่อ ฉายจอ หรือพิมพ์ในแชท ให้เปลี่ยนก่อนรัน `demo-reset.php`
- [ ] `https://<ชื่อ>.ngrok-free.app/phpmyadmin/`, `/server-status` และ `/.env` ต้องตอบ 403 ถ้าไม่ใช่ ให้ปิด ngrok ทันที
- [ ] `/api/v1/config` แสดง `"demo_code_required":true`
- [ ] มือถือ (ปิด Wi-Fi ใช้ mobile data) กรอกรหัสแล้วสั่งได้ และรหัสผิดเข้าไม่ได้
- [ ] ร้านและผู้ดูแลใช้ `http://localhost:8080/` บนโน้ตบุ๊ก ไม่เปิดผ่าน URL สาธารณะ

**หน้าเตือนและ URL ของ ngrok**

- แพ็กเกจฟรีแสดงหน้าเตือนก่อนเข้าครั้งแรกของแต่ละเบราว์เซอร์ ให้ผู้ชมกด "Visit Site" เปิดผ่านไว้ก่อนบนเครื่องที่ใช้สาธิต
- ถ้าไม่ได้ใช้ domain ที่จองไว้ URL อาจเปลี่ยนทุกครั้งที่เปิด ต้องแก้ `APP_URL` ทำ QR ใหม่ และ login ใหม่ เพราะ cookie ผูกกับ URL เดิม
- แพ็กเกจฟรีจำกัดปริมาณคำขอ ถ้าผู้ชมมากให้เพิ่ม `POLL_SECONDS` เป็น 5 และดูโควตาในหน้า dashboard ของ ngrok

**หลังปิด**

- [ ] กด `Ctrl+C` ที่ ngrok แล้วตรวจว่า URL เปิดไม่ได้
- [ ] ล้าง `DEMO_ACCESS_CODE`, `TRUSTED_PROXY` และตั้ง `DEMO_PUBLIC=false`
- [ ] รัน `demo-reset.php --confirm` เพื่อตัดทุก session
- [ ] ทำหัวข้อ "หลังจบ"

## 5.1 สาธิตจ่ายออนไลน์ด้วย PromptPay (Stripe sandbox, ทางเลือก)

ทำตาม [payments.md](payments.md) หัวข้อ "ตั้ง webhook" ก่อนวันสาธิต แล้วตั้ง `PAYMENT_MODE=gateway` วันสาธิตใช้ลำดับนี้

ลูกค้าจ่ายตอนสั่ง (D44) ร้านเห็นออเดอร์เมื่อจ่ายสำเร็จแล้วเท่านั้น

1. เปิดบอร์ดร้านไว้ข้างหน้าลูกค้า ให้ผู้ชมเห็นว่ายังไม่มีออเดอร์ใหม่
2. ลูกค้าสั่งแบบ "จ่ายออนไลน์ (PromptPay)" (ยอด 10 บาทขึ้นไป) แล้วกดยืนยัน หน้าเดียวกันขึ้น QR ยอด และเวลานับถอยหลังทันที ชี้ให้ดูว่าบอร์ดร้านยังว่าง
3. ลูกค้ากดลิงก์ "เปิดหน้าทดสอบของ Stripe" แล้วเลือก authorize (sandbox ไม่ตัดเงินจริง)
4. หน้าลูกค้าขึ้น "ชำระแล้วออนไลน์" และ "รอร้านยืนยัน" เอง ส่วนบอร์ดร้านมีออเดอร์ใหม่พร้อมป้าย "ชำระแล้วออนไลน์" และกระดิ่งดัง ถ้า webhook ไม่มา ให้ลูกค้ากด "ตรวจสถานะการชำระ"
5. ร้านกด "รับออเดอร์" แล้ว "อาหารพร้อม" แล้วส่งมอบด้วย QR รับอาหาร โดยไม่มีขั้นรับเงิน
6. (ถ้ามีเวลา) สั่งอีกออเดอร์แบบจ่ายออนไลน์ แล้วกด "เปลี่ยนเป็นจ่ายที่ร้าน" ออเดอร์ไปถึงร้านทันทีเป็นจ่ายเงินสด

ก่อนวันสาธิตให้รัน `C:\xampp\php\php.exe scripts\stripe-sandbox-e2e.php` หนึ่งครั้ง เพื่อตรวจว่าคีย์ sandbox และหน้าทดสอบของ Stripe ยังใช้ได้ ถ้าปล่อย QR ไว้จนหมดเวลา (`PROMPTPAY_QR_MINUTES`) ออเดอร์จะถูกยกเลิกเอง

ถ้า Stripe หรือ ngrok มีปัญหา ให้ตั้ง `PAYMENT_MODE=manual` แล้วสาธิตแบบเดิม ห้ามฉายหน้าจอ `.env` หรือ Stripe Dashboard หน้า API keys

## 6. แก้ปัญหาเฉพาะหน้า

| อาการ | ทำ |
|---|---|
| มือถือเปิดไม่ได้ | ตรวจว่าอยู่เครือข่ายเดียวกัน ปิด mobile data และ VPN ตรวจ IP ใหม่ ลอง `/api/v1/health` จากโน้ตบุ๊กด้วย `<IP>` ถ้าโน้ตบุ๊กเปิดได้แต่มือถือไม่ได้ แปลว่า firewall, เครือข่ายเป็น Public หรือ Wi-Fi กันอุปกรณ์คุยกัน ให้เปลี่ยนไปใช้ hotspot |
| เน็ตหลุดกลางคัน | ต่อใหม่แล้วโหลดหน้าใหม่ ออเดอร์อยู่ใน server ไม่หาย (ถ้าไม่โหลดใหม่ ระบบรอนานขึ้นทุกครั้งที่ต่อไม่ได้ สูงสุด 60 วินาที) สำรอง: เปิดหน้าลูกค้าในหน้าต่างที่สามบนโน้ตบุ๊กด้วย `localhost:8080` |
| หน้าไม่อัปเดต | แตะหน้าจอให้แท็บอยู่ด้านหน้า (แท็บที่ซ่อนหยุดอัปเดตโดยตั้งใจ) แล้วโหลดใหม่ ตรวจ `poll_seconds` ที่ `/api/v1/config` หน้า admin ไม่อัปเดตเอง ต้องโหลดใหม่ |
| ลืมรหัสผ่าน | ดู `SEED_DEMO_PASSWORD` ใน `.env` โดยไม่ฉายจอ ถ้าเพิ่งแก้ค่านี้ต้อง reset เพื่อให้มีผล |
| login ผิดจนติด 429 | รอ 15 นาที หรือ reset |
| มือถือค้างที่ออเดอร์เก่า/401 หลัง reset | เปิด `/customer/` ใหม่แล้วแตะชื่อลูกค้า (user และออเดอร์เริ่มนับใหม่) |
| ต้อง reset กลางคัน | รัน `demo-reset.php --confirm` แล้ว login ร้านและผู้ดูแลใหม่ โหลดมือถือใหม่ (ใช้เวลาไม่ถึงนาที) |
| ร้านปิด/สั่งไม่ได้ | ร้านกด "เปิดรับออเดอร์" ร้านสาธิตไม่กำหนดเวลาเปิดปิด จึงสั่งได้ทุกวันทุกเวลา |
| ngrok ขึ้น `ERR_NGROK_8012`/502 | Apache port 8080 ไม่ได้รัน หรือไม่ได้ใช้ `127.0.0.1` ในคำสั่ง |
| ผ่าน ngrok แล้วตอบ `CROSS_ORIGIN` | `TRUSTED_PROXY` ไม่ได้ตั้ง หรือใช้ `--host-header=rewrite` |
| ผู้ชมใส่รหัสแล้วติด 429 | มีคนบน IP เดียวกันใส่ผิดเกิน 20 ครั้ง รอ 15 นาที หรือ reset |
| Apache เริ่มไม่ได้ | port 8080 ถูกใช้: `netstat -ano \| findstr :8080` ปิดโปรแกรมนั้น หรือเปลี่ยนเลข port ทั้งใน vhost, firewall และ URL |
| reset ล้มเหลวกลางทาง | ตรวจว่า MySQL รันอยู่ แล้วรันคำสั่งเดิมซ้ำ |
