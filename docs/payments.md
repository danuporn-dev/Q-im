# ชำระเงินออนไลน์ด้วย PromptPay ผ่าน Stripe (D42, D44)

เอกสารนี้สำหรับผู้ดูแลระบบและผู้สาธิต อธิบายการเปิดใช้ การตั้ง webhook การกลับไปใช้แบบเดิม และข้อจำกัด รายละเอียดการตัดสินใจอยู่ใน [decisions.md](decisions.md) (D42, D44)

## ภาพรวม

มีสองโหมด ตั้งด้วย `PAYMENT_MODE` ใน `.env`

| โหมด | ลูกค้าเลือกได้ | ใครยืนยันว่าจ่ายแล้ว |
|---|---|---|
| `manual` (ค่าเริ่มต้น) | ชำระที่ร้าน, PromptPay เบอร์ร้าน (D38) | ร้านกด "ได้รับเงินแล้ว" เอง |
| `gateway` | ชำระที่ร้าน, **จ่ายออนไลน์ (PromptPay)** | เงินสด: ร้านกดเอง; ออนไลน์: Stripe ผ่าน webhook (ร้านไม่ต้องกด) |

ในโหมด `gateway` ตัวเลือก PromptPay เบอร์ร้านถูกซ่อนแต่โค้ดยังอยู่ ใช้ได้เมื่อกลับไปโหมด `manual`

## ขั้นตอน (PAYMENT_MODE=gateway): จ่ายตอนสั่ง (D44)

ตั้งแต่ D44 ลูกค้าจ่ายออนไลน์ทันทีตอนสั่ง ไม่ต้องรอร้านรับก่อน (แทนส่วน "จ่ายหลังร้านรับ" ของ D42)

1. ลูกค้าเลือก "จ่ายออนไลน์ (PromptPay)" ตอนยืนยันออเดอร์ (ยอดต้องไม่ต่ำกว่า 10 บาท ซึ่งเป็นขั้นต่ำของ Stripe)
2. ระบบสร้างออเดอร์สถานะ `AWAITING_PAYMENT` พร้อมเวลาครบกำหนด `pay_by` = เวลาสั่ง + `PROMPTPAY_QR_MINUTES` (ค่าเริ่มต้น 10 นาที) แล้วสร้าง PaymentIntent ที่ Stripe ทันทีด้วยยอดและสกุลเงิน (THB) จากออเดอร์ในฐานข้อมูล
   - ใช้ `Idempotency-Key` คงที่ต่อออเดอร์ (`qim-order-<เลขออเดอร์>-<id>-<ครั้งที่>` มีเลขออเดอร์สุ่มเพราะ id เริ่มใหม่เมื่อสร้างฐานข้อมูลใหม่ ส่วนการยกเลิกใช้ `qim-cancel-<รหัส PaymentIntent>`) กดซ้ำหรือกดพร้อมกันจึงได้รายการเดิม
   - ร้าน **มองไม่เห็น** ออเดอร์นี้ ไม่อยู่ในบอร์ด ประวัติ กระดิ่ง รายงาน และไม่นับใน Crowd Level จนกว่าจะจ่ายสำเร็จ
3. หน้าเดียวกันแสดง QR, ยอด, เวลานับถอยหลังถึง `pay_by`, ปุ่ม "ตรวจสถานะการชำระ", "บันทึกรูป QR" และ "เปลี่ยนเป็นจ่ายที่ร้าน"
   - ถ้า Stripe ไม่ตอบตอนสั่ง ออเดอร์ยังอยู่ หน้าออเดอร์มีปุ่ม "สร้าง QR จ่าย" ให้ลองใหม่ หรือเปลี่ยนเป็นจ่ายที่ร้าน
4. ลูกค้าสแกนจ่าย แล้ว Stripe ส่ง `payment_intent.succeeded` มาที่ `POST /api/webhooks/stripe` ระบบตรวจเลขออเดอร์ใน metadata รหัส PaymentIntent ยอด และสกุลเงินว่าตรงกับออเดอร์ ถ้าตรง ใน transaction เดียวระบบจะ:
   - ตั้ง `PAID` วิธี `STRIPE_PROMPTPAY`
   - เปลี่ยนออเดอร์จาก `AWAITING_PAYMENT` เป็น `PENDING` (บันทึก `placed_at` และ log โดยระบบ)
   - ร้านจึงเห็นออเดอร์ และกระดิ่งดัง
   - ถ้าไม่ตรง ระบบบันทึกเป็นรายการผิดปกติ (audit `payment.gateway_mismatch`) ไม่ตั้ง `PAID` และออเดอร์ไม่ไปถึงร้าน
5. ถ้า webhook ยังไม่ได้ตั้งหรือมาช้า ลูกค้ากด "ตรวจสถานะการชำระ" ได้ server จะอ่าน PaymentIntent จาก Stripe โดยตรง (จำกัด 12 ครั้งต่อนาที) หน้าเว็บของลูกค้าตั้ง `PAID` เองไม่ได้
6. ร้านเห็นป้าย "ชำระแล้วออนไลน์" รับออเดอร์ ทำอาหาร แล้วส่งมอบด้วยการสแกน QR รับอาหาร โดยไม่มีขั้น "ได้รับเงินแล้ว"

**หมดเวลาชำระ:** ออเดอร์ `AWAITING_PAYMENT` ที่เลย `pay_by` จะถูกยกเลิกเป็น `CANCELLED` (เหตุผล "หมดเวลาชำระเงิน") โดยระบบ มีสองทาง:

- `scripts/notify.php` ทุกนาที (ทำงานในโหมด gateway แม้ยังไม่ได้ตั้ง LINE)
- ตอนลูกค้าเปิดออเดอร์หรือรายการออเดอร์ เมื่อเวลานับถอยหลังบนหน้าเว็บถึงศูนย์ หน้าจะถาม server เอง

ก่อนยกเลิก ระบบขอให้ Stripe ยกเลิก PaymentIntent ก่อน:

- ถ้า Stripe บอกว่าจ่ายสำเร็จไปแล้ว (เงินเข้าก่อนครบกำหนด แต่ webhook ยังมาไม่ถึง) ออเดอร์ไปถึงร้านตามปกติ
- ถ้าติดต่อ Stripe ไม่ได้ ระบบยกเลิกออเดอร์ตามเวลาอยู่ดี ถ้าเงินเข้ามาภายหลัง ระบบตั้ง "รอคืนเงิน" และไม่ฟื้นออเดอร์

**เปลี่ยนเป็นจ่ายที่ร้าน** (ทำได้เฉพาะตอน `AWAITING_PAYMENT` และยังไม่เลยกำหนด):

- ระบบยกเลิก PaymentIntent ที่ Stripe ก่อน เมื่อยกเลิกสำเร็จจึงเปลี่ยนเป็นจ่ายที่ร้าน และส่งออเดอร์ถึงร้านเป็น `PENDING` ทันที
- ถ้าธนาคารกำลังดำเนินการ (`processing`) หรือจ่ายสำเร็จไปแล้ว ระบบปฏิเสธพร้อมบอกเหตุผล กรณีจ่ายสำเร็จแล้ว ระบบบันทึกการจ่ายและส่งออเดอร์ถึงร้าน
- การเริ่มจ่าย ตรวจสถานะ เปลี่ยนวิธี และยกเลิกเมื่อหมดเวลาของออเดอร์เดียวกัน ทำทีละคำขอ (named lock ต่อออเดอร์) และทุกทางเปลี่ยนออเดอร์ภายใต้ row lock เหมือน webhook ออเดอร์จึงไม่ถูกจ่ายสองทาง และไปถึงร้านครั้งเดียว

ลูกค้ายกเลิกออเดอร์ `AWAITING_PAYMENT` เองไม่ได้ ให้เปลี่ยนเป็นจ่ายที่ร้าน หรือปล่อยให้หมดเวลา

## รอคืนเงิน (REFUND_DUE) และการคืนเงิน

ระบบไม่เรียก refund API การคืนเงินต้องทำเองใน Stripe Dashboard เพราะ PromptPay คืนเข้าบัญชีธนาคาร และ Stripe จะส่งอีเมลขอเลขบัญชีจากลูกค้า ระบบมีหน้าที่บันทึกว่ามีเงินต้องคืนและคืนแล้วเท่านั้น

รายการจะขึ้น "รอคืนเงิน" เมื่อ:

- ร้านปฏิเสธหรือยกเลิกออเดอร์ที่จ่ายออนไลน์แล้ว (ยังต้องใส่เหตุผลเหมือนเดิม) ลูกค้าเห็นข้อความว่าจะได้รับเงินคืนทั้งในหน้าออเดอร์และข้อความ LINE
- เงินเข้ามาหลังหมดเวลาชำระหรือหลังออเดอร์ถูกยกเลิก (ออเดอร์ไม่ถูกฟื้น)
- ออเดอร์ชำระด้วยเงินสดไปแล้ว แต่เงินออนไลน์เข้ามาอีก (จ่ายซ้ำ)

วิธีคืนเงิน:

1. ร้านเปิดเมนู **รอคืนเงิน** หรือผู้ดูแลเปิด **ชำระออนไลน์** แล้วดูรหัส Stripe (`pi_...`)
2. เปิด Stripe Dashboard › Payments ค้นหารหัสนั้น แล้วกด Refund
3. กลับมากด "ทำเครื่องหมายคืนเงินแล้ว" พร้อมบันทึก เช่น เลขอ้างอิง ระบบบันทึก audit `payment.refunded` และเปลี่ยนการชำระของออเดอร์ที่ถูกยกเลิกหรือปฏิเสธเป็น `REFUNDED`

หน้าผู้ดูแลแสดงรายการที่ยอดหรือออเดอร์ไม่ตรงด้วย ให้ตรวจใน Stripe Dashboard ก่อนตัดสินใจ ยอดขายในรายงานไม่นับออเดอร์ที่ถูกปฏิเสธหรือยกเลิกหลังจ่าย จำนวนออเดอร์ในรายงานนับเฉพาะออเดอร์ที่ไปถึงร้าน (ออเดอร์ที่หมดเวลาชำระไม่นับ)

## เงื่อนไข sandbox

- `STRIPE_SECRET_KEY` ต้องขึ้นต้น `sk_test_` ระบบปฏิเสธคีย์อื่นทุกชนิด (`sk_live_`, `rk_`, `pk_`) คีย์ live ใช้ได้เฉพาะเมื่อ `APP_ENV=production` และ `STRIPE_ALLOW_LIVE=1` ซึ่งยังไม่ได้ทดสอบเลย
- Stripe บังคับให้ส่งอีเมลผู้ชำระสำหรับ PromptPay ระบบไม่เก็บอีเมลลูกค้าเพิ่ม จึงส่ง `STRIPE_PLACEHOLDER_EMAIL` ซึ่งเป็นอีเมลเดียวของผู้ดูแลทุกครั้ง ถ้าไม่ตั้งค่านี้ Stripe จะปฏิเสธการสร้าง QR และลูกค้าจะเห็น "ระบบชำระเงินออนไลน์ไม่ตอบ"
- ในโหมดทดสอบ หน้าออเดอร์มีลิงก์ "เปิดหน้าทดสอบของ Stripe" ซึ่งเป็นหน้า Stripe สำหรับกดอนุมัติหรือทำให้การจ่ายล้มเหลว คีย์ live ไม่แสดงลิงก์นี้
- ตรวจคีย์กับ Stripe จริง (ไม่แสดงคีย์ สร้างแล้วยกเลิก PaymentIntent 20 บาท):

  ```powershell
  C:\xampp\php\php.exe scripts\stripe-smoke.php
  ```

## ตั้ง webhook (ทำเอง)

webhook ต้องเป็น HTTPS ที่ Stripe เรียกถึง ถ้าสาธิตจากโน้ตบุ๊กให้ใช้ ngrok แบบ domain คงที่ เพื่อไม่ต้องแก้ใน Stripe ทุกครั้งที่เปิด

1. ทำตาม [demo.md](demo.md) หัวข้อ 5 (VirtualHost port 8080, ห้ามเปิด port 80)
2. จอง domain คงที่ฟรีใน ngrok dashboard (Domains) แล้วเปิด ngrok ด้วย domain นั้นตามเอกสาร ngrok รุ่นที่ใช้อยู่ (ตรวจชื่อ option ในเอกสาร ngrok เพราะเปลี่ยนตามรุ่น)
3. Stripe Dashboard (sandbox) › Developers › Webhooks › Add endpoint
   - URL: `https://<domain คงที่>/api/webhooks/stripe`
   - Events: `payment_intent.succeeded`, `payment_intent.payment_failed`, `payment_intent.canceled`, `payment_intent.processing`
4. คัดลอก Signing secret (`whsec_...`) ใส่ `STRIPE_WEBHOOK_SECRET` ใน `.env` ห้ามส่งต่อหรือ commit
5. ตั้ง `PAYMENT_MODE=gateway` และ `STRIPE_PLACEHOLDER_EMAIL` แล้วรัน `C:\xampp\php\php.exe scripts\migrate.php`
6. ทดสอบ: สั่งออเดอร์แบบจ่ายออนไลน์ แล้วให้ร้านรับออเดอร์ กด "แสดง QR จ่าย" แล้วกดลิงก์หน้าทดสอบของ Stripe เลือก authorize หน้าออเดอร์ต้องขึ้น "ชำระแล้วออนไลน์" เอง และใน Stripe Dashboard › Webhooks ต้องเห็นการส่งที่ได้ 200

ระบบตอบ webhook ดังนี้:

| คำตอบ | กรณี |
|---|---|
| 200 | จัดการแล้ว รวมถึง event ซ้ำ และ event ที่ไม่เกี่ยวข้อง |
| 400 | ลายเซ็นผิด, ไม่มีลายเซ็น, เวลาห่างเกิน 5 นาที หรือ payload ถูกแก้ |
| 503 | ยังไม่ตั้ง `STRIPE_WEBHOOK_SECRET` |
| 500 | ฐานข้อมูลขัดข้อง Stripe จะส่งซ้ำเอง |

ถ้า ngrok แสดงหน้าเตือน ให้ตรวจในหน้า Webhooks ของ Stripe ว่าคำขอได้ 200 ไม่ใช่หน้า HTML ของ ngrok

## กลับไปใช้แบบเดิม

ตั้ง `PAYMENT_MODE=manual` (หรือลบบรรทัดนั้น) ใน `.env` มีผลทันที

- ออเดอร์ใหม่เลือกได้เฉพาะชำระที่ร้านและ PromptPay เบอร์ร้านตามเดิม
- ออเดอร์ออนไลน์ที่ค้างอยู่ยังรับ webhook ได้ถ้ายังตั้ง secret ไว้
- ร้านยังส่งมอบออเดอร์ที่ยังไม่จ่ายโดยรับเงินสดได้

## ข้อจำกัด

- **เงินเข้าบัญชี Stripe บัญชีเดียว** ของผู้สมัคร Stripe ยังไม่มีการแบ่งจ่ายให้หลายร้าน (Stripe Connect) การโอนให้แต่ละร้านต้องทำนอกระบบ
- การคืนเงินทำเองใน Stripe Dashboard ระบบแค่บันทึก
- Stripe ไม่ระบุอายุ QR ของ PromptPay เวลาครบกำหนดเป็นของระบบเอง (`PROMPTPAY_QR_MINUTES`) เมื่อครบกำหนดระบบยกเลิก PaymentIntent ถ้ายกเลิกไม่ได้เพราะติดต่อ Stripe ไม่ได้ เงินที่เข้ามาภายหลังจะเป็น "รอคืนเงิน"
- ทุกคำขอไป Stripe ระบุ `Stripe-Version` คงที่ (`StripeGateway::API_VERSION`) การเปลี่ยน version ตั้งต้นใน Dashboard จึงไม่กระทบระบบ ถ้าจะเปลี่ยนค่านี้ในโค้ด ให้รัน `stripe-smoke.php` และ `stripe-sandbox-e2e.php` ใหม่
- ร้านที่ปิดรับหรือออเดอร์เต็มหลังลูกค้าจ่ายแล้ว ยังได้รับออเดอร์ที่จ่ายแล้ว (ตรวจตอนสั่งเท่านั้น) ร้านปฏิเสธได้และระบบตั้งรอคืนเงิน
- PromptPay ของ Stripe ใช้ได้กับบัญชีธุรกิจในไทยและลูกค้าในไทยเท่านั้น (ตามเอกสาร Stripe)

## ทดสอบโดยไม่เรียก Stripe

เทสต์ (`tests/28_gateway.php`, `tests/29_gateway_browser.php`) และ e2e ใช้ `FakeGateway` (`PAYMENT_GATEWAY=fake` ใช้ได้เฉพาะ development) และส่ง webhook ที่เซ็นด้วย secret ปลอมเอง เทสต์ไม่เรียก Stripe จริงเลย ชุดเทสต์บังคับ `PAYMENT_MODE=manual` และล้างคีย์ Stripe ของ `.env` ทุกครั้ง (`tests/testdb.php`) เซิร์ฟเวอร์เทสต์ที่ต้องจ่ายออนไลน์ตั้ง FakeGateway เอง

## ทดสอบกับ Stripe sandbox จริง

```powershell
C:\xampp\php\php.exe scripts\stripe-sandbox-e2e.php
```

สคริปต์ใช้คีย์ `sk_test_` ใน `.env` กับฐานข้อมูลทิ้งได้ `qim_test` (ไม่แตะ `qim_dev`) และต้องมี Chrome หรือ Edge ทำตามลำดับนี้:

1. สั่งแบบจ่ายออนไลน์ และตรวจว่าได้ QR ทันทีและร้านยังไม่เห็นออเดอร์
2. เปิดหน้าทดสอบของ Stripe ใน headless browser แล้วกด authorize (ลองได้ไม่เกิน 3 ครั้ง)
3. ตรวจกับ Stripe ด้วย "ตรวจสถานะการชำระ" (reconcile) เพราะ webhook มาไม่ถึงเครื่องนี้
4. ตรวจว่าออเดอร์ไปถึงร้านเป็น `PENDING` และ `PAID` แล้วรับ พร้อม และส่งมอบด้วย QR

## สิ่งที่ยังไม่ได้ทดสอบกับ Stripe จริง

ตรวจกับ sandbox จริงแล้ว:

- การสร้าง อ่าน และยกเลิก PaymentIntent (`stripe-smoke.php`)
- ทั้ง flow จ่ายตอนสั่งผ่านหน้าทดสอบของ Stripe แล้วตรวจกับ Stripe (`stripe-sandbox-e2e.php`)
